# UI 개선 2단계 — 검색 조건 구현·검증

## 1. 증상 분석

기준은 `6a55893`(UI 1단계 PR #67 머지)이다. `AGENTS.md`, 최신 코드와 원격 이력을 확인했고 작업 시작 시 추가 원격 커밋·로컬 변경이 없었다. 기준 코드의 실제 로컬 Chromium 화면을 360/390/430/1366px에서 확인했다. 다섯 조건 화면이 모든 필터를 펼쳐 놓았고, 사용 중인 필터를 한 번에 확인/해제하는 요약이 없었다.

P1의 조회 설명과 실패 재시도 검사는 있었지만 공통 결과 조건 UI가 없었다. 값이 원래대로 돌아와도 변경 횟수가 다르면 재시도를 막을 수 있었다. 일반지도의 결과 목록·범례·맞춤은 결과를 만든 조건 대신 현재 편집 중인 소스 체크박스를 다시 읽었다.

## 2. 가설 수립 / 3. 검증 결과

| 가설 | 확인·검증 |
| --- | --- |
| 모든 범위·설명을 한 번에 노출해 검색 영역이 길어진다 | 맞음. 기본 커밋 화면과 DOM을 확인하고 같은 네 너비의 전후 캡처로 검증 |
| 편집값과 결과 스냅샷의 공통 경계가 부족해 안내·재시도가 어긋난다 | 맞음. P1 변경 횟수/DOM 비교 경로와 지도 재렌더 경로 추적. 조건 변경·원상복귀·늦은 페이지·실패 범위 재시도·History 재생으로 검증 |
| DOM 값만 바꾸면 다중선택 Set·슬라이더와 불일치할 수 있다 | 맞음. 컴포넌트 내부 상태를 확인. 공통 `set()`을 확장하고 칩/프리셋/URL/실제 검색값의 양방향 일치를 브라우저에서 검증 |

## 4. 근본 원인

각 필터의 기본값·표현·실제 적용값을 공통으로 다루는 경계와 결과에 연결된 조건 스냅샷이 부족했다. 기존 컴포넌트를 교체하지 않고 설정 API를 확장하고, 확정된 값에만 기반한 요약·동등성·조회 스냅샷을 연결했다. P1 요청 소유권·실패 집계·부분 재시도와 P2 단계적 표시는 그대로 유지했다.

## 5. 구현 내용

### 화면별 기본·상세 구성

| 화면 | 기본 조건 | 접힌 상세 조건 |
| --- | --- | --- |
| 건축물 조건검색 | 행정동, 용도 | 구조, 지상·지하층수, 연면적, 사용승인 연도, 연도 미확인 포함 |
| 공동주택 | 행정동, 주택 종류 | 세대수, 연면적, 사용승인 연도, 면적·연도 미확인 포함 |
| 철거·멸실 | 행정동, 철거·멸실 연도 | 철거·멸실 구분, 날짜 미확인 포함 |
| 빈집 | 행정동, 등급 | 건축년도, 연도 미확인 포함 |
| 일반지도 | 표시할 자료, 행정동 | 선택 자료의 빈집 등급·주택 종류·건축물 용도/구조 |

- 기존 DOM 컨트롤을 공통 어댑터로 이동했다. 조건·선택 가능한 값·검색 산식·데이터를 삭제/변경하지 않았다. 검색 동작은 기존 컴포넌트가 갖는 값과 Set을 그대로 읽는다.
- 상세 조건은 처음 접히며 `상세 조건 · N개 적용`으로 숨은 적용값을 알린다. 공유/최근 검색 복원도 같은 값·칩·개수로 갱신한다. 펼침 상태는 URL/최근 검색/검색 필터/History에 저장하지 않는다.
- 검색·취소·초기화는 상세 조건 아래의 공통 동작 영역에 유지하고 검색 중에도 접근할 수 있도록 sticky 배치를 적용했다. 지도는 기존 제한 높이 패널을 세로 스크롤할 수 있게 하여 결과·필터가 잘리지 않게 했다.

### 칩과 조건 개수 기준

- **기본값과 다른 필터 컨트롤 1개 = 조건 그룹 1개**다. 다중선택에서 용도 3개를 골라도 1개, 최소/최대 한 쌍은 1개다. 미확인 포함 체크는 범위와 독립된 1개다. 정렬·페이지·선택 상세·펼침 상태는 필터 개수에서 제외한다.
- 상세 적용 개수는 그 중 상세 영역의 그룹만 센다. 지도는 현재 선택한 자료에 실제 적용되는 추가 필터만 센다. 자료를 해제해도 그 자료의 필터값은 저장하며 다시 선택하면 살아난다. 미사용 필터는 별도로 `미사용 저장 N개`로 표시하고, 실제 적용 조건이 0개라도 전체 해제로 지울 수 있다. 미사용 필터를 변경해도 결과가 달라지는 조건으로 오인하지 않는다.
- 칩은 다중선택 값을 나열하고 범위의 실제 의미를 표시한다. 예: `지상층수 5층 이상`, `사용승인 연도 2000년 이하`. 범위에 미확인 값도 포함하면 그 사실을 함께 표시하고, 기본 포함을 해제하면 별도 `연도 미확인 제외` 칩을 표시한다.
- 칩의 ×는 **그 컨트롤만** 기본값으로 되돌린다. 연도 범위 해제는 미확인 포함 체크를 바꾸지 않는다. 각 해제 버튼에는 `사용승인 연도 조건 해제` 등 접근 가능한 이름을 제공한다.
- `조건 모두 지우기`: **현재 화면 필터만** 기본값으로 되돌리고 기존 결과는 유지한다. 다른 메뉴는 건드리지 않고 자동 조회하지 않는다. 기존 `초기화`는 해당 화면의 결과/진행/선택까지 지우는 기존 역할을 유지한다. 이 차이를 도구 근처에서도 안내한다.

### 빠른 조건의 정확한 규칙

모든 빠른 조건은 값만 설정하며 검색은 사용자가 실행한다. 행정동 등 담당하지 않는 필드는 유지한다. 버튼의 선택 표시는 실제 필터값과의 동등성에서 계산하므로 직접 수정하면 즉시 해제된다. 서로 다른 필드는 조합하고 같은 필드는 나중 값으로 덮어쓴다. 이미 정확히 적용된 버튼을 다시 누르면 **그 빠른 조건이 담당하는 필드만 기본값**으로 되돌린다(적용 전 값의 undo가 아님).

| 화면·빠른 조건 | 설정하는 필드 | 해제 |
| --- | --- | --- |
| 건축물·공동주택 | 용도 = 공동주택 | 용도만 전체 |
| 건축물·사용승인 30년 이상 | 승인 연도 최소 1900, 최대 `올해−30`, 연도 미확인 제외 | 승인 연도 전체 + 미확인 기본 포함 |
| 공동주택·아파트 | 주택 종류 = 아파트 | 종류만 전체 |
| 공동주택·300세대 이상 | 세대수 최소 300, 최대 컨트롤 상한(기존 무제한 의미) | 세대수만 전체 |
| 빈집·3등급 | 등급 = 3등급 | 등급만 전체 |
| 철거·멸실·최근 5개년 | 최소 `올해−4`, 최대 올해, 날짜 미확인 제외 | 연도 전체 + 미확인 기본 포함 |

2026년 기준 30년 조건은 **1996년 이하**, 최근 5개년은 **2022~2026년(올해 포함)**이다. 연도 차이 기준이며 정확한 날짜 경과나 위험/안전등급이 아니다. 설명에서 이 기준과 미확인 제외를 명시했다. 철거 연도 입력 상한도 초기화 시 올해로 맞춰 다음 연도에 5개년 버튼이 범위를 벗어나지 않게 했다.

저장소의 실제 빈집 파일에는 648레코드·1/2/3등급이 있었다. 4등급 빠른 조건은 만들지 않았다. 빠른 조건의 값이 실제 옵션/입력 범위에서 제공되지 않으면 버튼을 비활성화한다. 일반지도에 현재 필터로 정확히 표현할 수 없는 추가 빠른 조건을 억지로 만들지 않았다.

### 범위 입력·URL

- 기존 숫자 직접 입력과 슬라이더는 유지한다. 두 컨트롤의 `set()`이 실제 내부 값과 화면을 함께 갱신한다. 연도 단위도 입력 레이블에 표시한다.
- 전체 범위는 `전체`, 기존 상한 무제한 컨트롤은 `5층 이상`처럼 표시한다. 건축물 사용승인 연도/빈집 건축년도/철거 연도는 기존 유한 범위 의미를 유지하고, 공동주택 승인 연도 상한은 기존 무제한 의미를 유지한다.
- 반복 안내는 접힌 `범위 입력 안내`로 이동하되 `최대 30층 = 상한 무제한` 같은 중요한 의미는 입력 가까이에 남긴다. 빈 값·역전·경계 밖 값은 기존 정규화 함수를 재사용하고 적용값을 입력/슬라이더/요약/URL에 같이 반영한다.
- 숫자를 타이핑하는 동안은 별도 미완성 값이다. `change`/Enter로 확정하기 전에는 칩·조회 비교·공유 상태에 새 값으로 기록하지 않는다. 공유/저장 버튼을 클릭해 포커스를 옮기면 브라우저의 정상 확정 과정을 거친다.
- URL 버전/필드/탭 생략 호환성은 **v1 그대로**다. 빠른 조건 이름이나 펼침 상태를 저장하지 않고 실제 필터만 저장한다. 최근 검색 요약도 범위·상한 의미를 반영한다.

### 편집 중인 조건과 결과의 조회 조건

- 조회 시작 시 실제 사용한 필터를 독립 스냅샷으로 잡고, 결과를 게시할 때 그 스냅샷을 결과에 연결한다. 건수 근처와 결과 안내에 **표시 결과의 조회 조건**을 별도로 표시한다.
- 편집값이 다르면 `조건이 바뀌었어요. 다시 검색해 주세요. 이전 조건의 결과입니다.`와 재검색 동작을 제공한다. 실행 중 변경도 변경 전 조건의 조회임을 표시한다. 값 변경만으로 외부 검색을 실행하지 않는다.
- 원래 값으로 되돌리면 안내가 사라진다. 실패 요청 재시도도 확정된 실제 필터값이 원래와 같을 때만 허용한다. 변경 횟수나 임시 입력 문자열, 정렬·페이지·펼침은 동일성의 기준으로 삼지 않는다. 재시도 도중 조건이 바뀌면 기존 P1/P2의 소유권/조건 검사를 통해 커밋을 막는다.
- 조회 중·보강 중·부분 조회·전체 실패·취소는 기존 ledger/보강 상태를 사용한다. 실패·미확인·정상 0건을 합치지 않고, 지도는 처리 완료와 도형/출처의 완전성을 별개로 안내한다. 중요한 안내에는 만료 타이머를 붙이지 않았다.
- 일반지도 결과 목록·범례·도형 표시 범위도 **조회 당시 소스**를 따른다. 체크박스를 바꿨다고 기존 결과를 새 소스로 다시 해석하지 않는다. 입력에 필요한 필터 섹션의 노출은 편집값을 따른다.
- 결과 엑셀은 기존 데이터 시트·P1 조회정보를 유지하고 **`결과조회조건` 시트**에 실제 게시 결과의 필터·요약·시각·상태를 기록한다. 공동주택의 기존 보강 정보도 결과 소유 세션을 따른다. **링크/조건 파일은 현재 편집값**, **결과 엑셀은 실제 결과 조건**이라는 차이를 저장 도구에서 안내한다.

### History·최근 검색·복원

- 첫 편집만 초안 이력으로 분리하고 이후 값 확정/칩/빠른 조건은 replace를 사용한다. 여러 항목을 바꾸는 빠른 조건도 한 번의 확정 이벤트로 기록한다. 슬라이더 이동마다 push하지 않는다.
- 브라우저 이력에 `resultConditions`라는 선택적 메타데이터를 추가했다. 내용은 기존 v1 형식의 **마지막 조회 조건뿐**이며 응답/도형/인증정보는 없다. 공유 URL에는 포함하지 않는다.
- 뒤로/앞으로·새로고침에서 편집 조건과 이전 조회 조건이 다르면, 이전 조건의 특정 동 조회/정적 자료를 기존 정상 캐시로 재조회한 뒤 편집값을 다시 적용해 둘의 관계를 복원한다. **동구 전역·대량/일괄 검색은 자동 재실행하지 않는다.** 필요한 경우 이전 조건만 안내하고 수동 검색하도록 한다. 결과 자체를 브라우저 기록에 저장하거나 시점이 같은 결과라고 보장하지 않는다.
- 명시적 URL이 우선이며 선택적 이력 메타데이터가 잘못돼도 URL 복원을 막지 않는다. 최근 검색의 최대 10개·일괄주소 자동 저장 제외·개별/전체 삭제·조건만 복원 정책은 유지한다.

### 변경 파일

- 신규 `filter-model.js`: 기본·상세 구성, 그룹·범위 요약, 적용성·동등성, 빠른 조건 정의의 순수 모듈.
- 신규 `filter-ui.js`: 기존 컴포넌트 어댑터, 접기/칩/빠른 조건, 실제 조회 스냅샷과 결과·엑셀·이력 연결.
- `index.html`: 컴포넌트 설정 API·정규화 표시, 조회 스냅샷 연결, 재시도 비교, 결과 소유 세션의 엑셀, 지도 결과 소스 보존, 관련 문구.
- `search-navigation.js`, `ui-enhancements.js`, `ui-labels.js`: 확정값 공유·복원·한 번의 편집 이력, 현재 편집/결과 조건 안내, 메뉴 이동 연계, 최근 검색 범위 표현.

### 남은 제한

- 모바일은 **Chromium 터치 에뮬레이션**이다. 물리적 휴대전화·iOS Safari·실제 스크린리더는 검증하지 않았다.
- 조회 브라우저 테스트는 **모의 지연/실패 API**와 실제 저장소의 빈집·행정동·단지 파일을 사용했다. 이번 단계에서 운영 외부 API를 대량 호출하거나 운영 전수 정확성·속도를 검증하지 않았다.
- 이력 재생은 현재 자료에 대한 재조회다. 캐시가 만료되면 허용된 특정 동 조회에 외부 요청이 생길 수 있다. 전체 동구의 이전 결과를 저장·자동 복구하지는 않는다.
- 기존 필터의 미기재 숫자 처리·연도 해상도·최대값 무제한 의미는 그대로다. 월/일 단위 노후 연수나 안전성 판정 기능은 추가하지 않았다.
- 검증 완료 후 사용자 요청에 따라 커밋·푸시·PR 머지를 진행한다(Git/PR 기록 참조). 화면 증거는 운영 배포 전 코드 기준이며 별도 배포 명령은 실행하지 않았다. Vercel 연동 시 푸시·머지로 자동 배포될 수 있다.
