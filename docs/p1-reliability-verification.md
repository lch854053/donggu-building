# P1 신뢰성 수정 및 검증 기록

- 확인일: 2026-10-25
- 기준: `lch854053/donggu-building`, `4ce11f3` (작업 시작 시 최신 HEAD)
- 원래 세션 경로는 다른 저장소(`donggurang-pay`)였으므로 승인된 임시 작업 경로에 대상 저장소를 새로 복제했다. 기존 작업 파일은 변경하지 않았다.
- 별도 배포 명령은 실행하지 않았다. 커밋·PR·머지는 검증 완료 후 사용자 요청에 따라 진행하며, 저장소의 Git/PR 기록을 참조한다. Vercel 연동 시 푸시·머지로 자동 배포가 실행될 수 있다.

## 1. 증상 분석

상세 탭은 하나의 패널을 공유하지만 비동기 완료 시 선택 상태를 검사하지 않았다. 페이지 수집은 자동 재시도 후 최종 실패 건수만 남겼으며, 필지 대표 GIS 값과 내진 누락값은 개별 건물의 확정 정보처럼 표시됐다.

## 2. 가설 수립

| 가설 | 확인할 증거 |
| --- | --- |
| A. 응답 소유권이 없어 이전 탭·주소 응답이 현재 화면을 덮는다 | `await` 뒤 전역 캐시·공유 패널 쓰기 경로, 지연 응답 역전 테스트 |
| B. 실패 범위가 소실되어 부분 결과 복구가 불가능하다 | 수집 루프의 실패 카운터, 첫 페이지 실패 처리, 엑셀·지도 경고 경로 |
| C. 값의 범위·누락·오류를 구분하지 않는다 | 대표 GIS 선택 코드, 실제 API 필드, 주소·가설·빈집·내진 분기 |

## 3. 가설 검증 결과

세 가설 모두 코드 흐름과 통제된 테스트에서 확인했다. 기존 `apiRetry`는 0/408/425/429/일부 5xx에 지수 백오프와 지터를 적용하고 있었으므로 유지했다. 최종 실패를 요청별로 보존하지 않는 점과 화면에 반영하는 시점의 검증 부재가 추가 수정 대상이었다.

### 실제 운영 API 확인 (전수 조회 없음)

운영 프록시에 정상 Origin 헤더를 지정해 읽기 요청했다. 키·인증정보는 요청하거나 저장하지 않았다.

| 요청 | 실제 관찰 |
| --- | --- |
| `/api/juso?keyword=서남로 1` | 서석동 31, 현행 행정코드 `1221011800`, 구 코드 건물관리번호 반환 |
| `/api/building?sigunguCd=29110&bjdongCd=11800&bun=0031&ji=0000` | 첫 요청은 HTTP 502, `API 응답 파싱 오류` |
| `/api/building?op=getBrTitleInfo&sigunguCd=12210&bjdongCd=11800&platGbCd=0&bun=0031&ji=0000&numOfRows=100&pageNo=1` | 후속 요청 HTTP 200, 표제부 3건 |
| `/api/vworld-bld?pnu=2911011800100310000` | HTTP 200, 대표 속성 `hg=15.7`, `dong_nm=주건축물제2동`, `violt_bild=N`, `last_updt_dt=2026-10-05Z` |

표제부 3건은 부속건축물(흙벽돌조, 내진 값 공백), 주건축물(철근콘크리트, 지상 6층, `heit=15.3`, 내진 `1`), 제2동(일반철골, 지상 4층, `heit=15.7`, 내진 `1`)이었다. GIS의 `gis_idntfc_no`·`buld_idntfc_no`·`refrn_systm_cntc_no`와 표제부의 `mgmBldrgstPk` 간 직접 연결은 확인하지 못했다. 이름·면적·층수가 일치해 보이는 것만으로 동별 매칭을 확정하지 않았다.

공식 [건축HUB 명세](https://www.data.go.kr/data/15134735/openapi.do) 및 해당 페이지의 [공식 활용가이드 ZIP](https://www.data.go.kr/cmm/cmm/fileDownload.do?atchFileId=FILE_000000003051351&fileDetailSn=1) 안 HWP를 확인했다. 가이드는 `rserthqkDsgnApplyYn`을 옵션 `VARCHAR(1)`, 설명을 **내진 설계 적용 여부(0,1)**, 예시를 `0`으로 명시하며 `rserthqkAblty`는 내진능력이다. 판독은 명시 코드 `1` 적용 / `0` 미적용 / 그 외 미확인으로 한정했다. 실제 운영 표본에서 확인한 코드는 `1`과 공백이며, `0`은 공식 가이드의 응답 예시와 모의 테스트로 확인했다. 현장 건물의 실제 내진 성능을 판정한 것은 아니다.

## 4. 근본 원인

비동기 요청의 수명과 조회 결과의 완전성, 데이터가 설명하는 공간 범위가 전역 화면 상태와 분리되어 있지 않았다. 오류를 빈 배열이나 기본 부정값으로 바꾸는 처리까지 겹쳐, 누락된 결과가 정상 결과처럼 보일 수 있었다.

건축물 데이터 수집 동시성은 2, 자동 재시도는 최대 3회다. 첫 페이지 실패·모순되는 건수·누락 페이지·100페이지 상한도 완전한 조회로 표시하지 않는다. 새 검색·초기화 시 이전 대기 작업을 중단하며, 이미 진행 중인 네트워크 요청은 완료되더라도 현재 화면·검색 기록에 반영하지 않는다. 실패 요청 재시도 중에는 기존 결과와 엑셀 메타데이터를 유지하고, 조건·세대가 동일할 때만 새 기록과 함께 교체한다.

정적 데이터 파일, 시군구코드 변환 규칙, 기존 엑셀 데이터 열은 변경하지 않았다. GIS 판정은 필지 대표정보로 한정하고, 선택 건물 높이는 대장 `heit`의 양수 값만 별도로 표시한다.

## 6. 검증 결과 및 제한

### 자동 테스트

- 의존성 설치: `npm ci`. 설치 전 첫 실행은 `proj4` 미설치로 실패했고, 설치 후 기존 테스트도 정상 실행했다.
- `node --test`: **133개 통과, 실패 0개** (신규 회귀 테스트 23개 포함). `git diff --check`도 통과했다. 추가 테스트는 아래 조건을 검증한다.
  - 탭 역전, 이력 → 가설, 폐쇄말소 층별 → 오수, 동 전환, 주소 재검색, 초기화, 지연된 지도 좌표
  - 부분 페이지 → 실패 페이지만 재시도 → 중복 없는 복구, 정렬·집계, 첫 페이지 실패와 정상 0건
  - 조건 변경/새 검색 도중 재시도 완료 시 결과·메타데이터 혼입 차단
  - 실제 XLSX 바이너리 쓰기/읽기로 조회 상태·범위·기존 데이터 열 확인
  - GIS 필지 대표정보, 내진 미확인, 가설 보강정보 실패 항목만 재시도, 빈집 로드 실패
  - 영구/형식 오류 무재시도, 제한된 동시성·페이지 상한, 안전한 로그, 지도 도형 배치의 성공/실패/없음

### 실제 브라우저 (로컬 UI + 통제된 응답)

`python3 -m http.server 3000`으로 정적 UI를 열고 브라우저 내 앱 함수·DOM·실제 버튼 핸들러에 지연/실패 응답을 주입했다. 이력 → 가설 및 폐쇄말소 층별 → 오수의 역전 응답 차단, 초기화, GIS 범위/미확인 표시, 조건조회와 철거멸실의 `1,2(실패),2(재시도)` 호출 순서, 실제 결과 표·정렬·집계 복구, 부분 조회 엑셀 생성 경로, 필터 변경 중 재시도 차단, 지도 렌더 후 건축물 경고 유지가 통과했다. 파일 다운로드 OS 대화상자를 수동 검증한 것은 아니며, 브라우저의 워크북 생성과 Node의 XLSX 바이너리 검증을 병행했다.

### 남은 제한

- 이 검증은 운영 배포 전 코드 기준이다. 별도 배포 명령이나 로컬 서버에 운영 키를 넣은 전체 서버리스 경로 검증은 수행하지 않았다.
- 계림2동의 과거 332/646건 차이 및 산수동 543-2의 실제 원본 전체 결과는 재조회·전수 대조하지 않았다. 실패·지연은 통제된 응답으로 검증했다. 외부 장애의 구체적 원인은 확정하지 않는다.
- GIS 원본 WFS 전체 객체/모든 식별자 연결을 직접 검증하지 않았으므로 동별 GIS 값은 추정하지 않는다. `D_BLDGIS`는 원래부터 대표 객체를 반환하는 프록시를 통해 확인했다.
- 이미 전송된 상세 요청을 모두 `AbortController`로 취소하지는 않는다. 세대 검사가 안전장치이며 새 검색의 페이지 대기 큐는 진행을 멈춘다.
- 동일 시점의 상류 페이지 데이터가 일관된 스냅샷이라는 보장은 없다. 조회 성공은 원본 데이터 전체의 정확성 검증을 의미하지 않는다.
- `npm ci`는 기존 `xlsx` 의존성에 high 취약점 1건을 보고했다. 이번 P1 범위 밖이므로 의존성 교체는 하지 않았다.
