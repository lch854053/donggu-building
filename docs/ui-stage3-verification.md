# UI 개선 3단계 — 결과 표시·상세 탐색

기준 커밋: `18012d1`(UI 2단계 PR #68 머지). 작업 전 `AGENTS.md`와 최신 코드·원격 이력을 확인했으며 작업 폴더는 깨끗했다. 프레임워크·의존성·필터 구성·원본 JSON·API·시군구/PNU 변환 규칙은 바꾸지 않았다. 검증 완료 후 사용자 요청에 따라 커밋·푸시·PR 머지를 진행한다(Git/PR 기록 참조). 별도 배포 명령은 실행하지 않았다.

## 1. 증상 분석

- 결과 건수, 실제 조회 조건, 요청 상태, 엑셀이 여러 위치에 흩어져 있었다. 요청 성공/실패 수·실패 페이지가 그대로 드러났고, 주소 조회의 `정상`이 건물의 적법성 판정으로 읽힐 수 있었다.
- PC 표는 모든 열을 처음부터 표시했다. 상세는 핵심 정보·세부 규모·보강 정보가 연속돼 있었고 일부 표시 함수는 `0`을 `-`로 숨겼다.
- REB 실제 저장 자료의 아파트 평균 매매가격은 `314507.575757576 천원`이었다. 기존 요약은 천원·만원·원과 긴 소수를 함께 표시했다. 공동주택 엑셀은 기존 `Math.round(d.tarea)`로 면적 정밀값을 잃고 있었다.
- 메뉴 이동은 P1/P3의 진행 조회 무효화 경계이므로 목록→일반지도 이동을 단순 재사용하면 원래 조회 맥락에 부작용이 생길 수 있었다.

## 2. 가설 수립 / 3. 검증 결과

| 가설 | 코드·데이터·브라우저 검증 |
| --- | --- |
| 결과 상태와 동작이 분산되어 핵심 판단이 어렵다 | 맞음. 결과 렌더러·`showQueryStatus()`·UI 2단계 스냅샷을 추적하고 완료/부분/0건/전체 실패/취소를 모의 응답으로 검증 |
| 전열 노출과 공통 표시 규칙 부족으로 가독성과 값 의미가 흔들린다 | 맞음. 기존 표 스키마, `useAprCell`, REB 원본 단위, 0 처리, 공동주택 내보내기를 대조. 숫자·단위·헤더 의미·원본 엑셀을 검증 |
| 일반 메뉴 전환 재사용이 원래 검색을 취소/초기화할 수 있다 | 맞음. P3 `stop()`과 요청 소유권 경계를 확인. 인라인 지도 및 명시적 새 탭 상세로 기존 목록을 유지하고 원래 필터/페이지/정렬/스크롤 불변 검증 |

추가로 실제 Chromium에서 두 문제를 재현했다.

- 지도 카드 폭은 **338px**인데 내부 표는 전역 `table{min-width:1080px}`를 상속했다. 카드 외부 가로 넘침이 없어도 내부 값이 잘릴 수 있었다. 지도 카드 표에만 최소 너비 예외를 적용하고 열린 다건 필지 카드의 표 폭까지 검증했다.
- 공동주택 상세 API가 늦게 완료되면 사용자가 위로 이동한 후에도 상세 행으로 강제 스크롤됐다. 지연 응답 시 **0→4324px**를 재현했고, 이동을 최초 열기 시점으로 옮긴 뒤 **0→0px**를 검증했다.
- 개발 중 시각 검토에서 조건검색 열 인덱스의 잘못된 대응도 발견했다. 실제 렌더러의 `주용도/주구조/연면적/지상층/지하층` 헤더와 값 대응을 바로잡고, 단순 인덱스 숫자 확인이 아닌 **헤더 이름별 값 검증**을 회귀에 추가했다.

## 4. 근본 원인

표시 규칙과 결과 요약이 공통화되지 않았고, 조회 상태와 건물 속성·결과 탐색과 메뉴 초기화의 경계가 명확하지 않았다. 기존 데이터·요청 소유권·UI 2단계 결과 스냅샷은 그대로 사용하면서 표시 어댑터와 순수 표시 함수를 추가했다. 중요한 경고를 접지 않고, 지연 응답은 읽던 상세·탭·스크롤을 불필요하게 바꾸지 않게 했다.

## 5. 구현

### 결과 요약·요청 상태

일괄주소/건축물 조건검색/공동주택/철거·멸실/빈집 결과에 같은 순서를 적용했다.

1. 결과 건수(일괄주소는 입력주소 수와 대장 확인 수 분리)
2. **실제 게시 결과의 조회 조건** — UI 2단계 `published` 스냅샷 사용
3. 조회 상태와 핵심 경고
4. 엑셀·결과표 이동 및 행에서 상세/위치를 확인할 수 있다는 안내
5. 접힌 조회 내역·표시 항목 설정

- `요청한 범위 조회 완료`, `조회 중 · 잠정 결과`, `일부 자료를 불러오지 못했습니다`, `자료를 불러오지 못했습니다`, `조건 일치 0건`, `조회 취소 · 미완료`를 구분한다. 완료는 원본 정확성·개별 건물의 적법성 보증이 아님을 표시한다.
- 기존 ledger와 공동주택 보강 상태를 읽는다. 새로운 검색 판정이나 성공/실패 합산 체계를 만들지 않았다. 새 시도가 취소된 경우 이전 실패 상태를 그대로 요약하지 않도록 시도/게시 결과를 구분했다.
- 성공 요청 수·실패 페이지는 `조회 내역 자세히`에 넣고, 기존 **실패 요청만 재시도 버튼 자체**를 결과 요약 안으로 이동했다. 기존 세션·조건 검사·클릭 핸들러를 재사용하며 복제 재시도를 만들지 않았다.
- UI 2단계의 편집 조건 칩, 이전 결과 경고, 원래 값으로 돌아왔을 때 안내 해제, 원래 조회 조건에서만 가능한 재시도, 조건 파일/링크와 결과 엑셀의 구분을 유지한다.
- 빈집은 `N개 원본 레코드`, `위치 연결 N개 레코드`, `지도 도형 N개`, `위치 미확인 N개 레코드`를 별도로 표시한다. 도형 수를 건물 수라고 부르지 않는다.
- 개별 주소의 `정상` 배지·통계를 `조회 완료`로 정리하고 위반 여부 판정이 아니라는 설명을 붙였다. 엑셀의 상태 문구도 같은 의미로 명확히 했다.
- 기존 취소 정책은 유지한다. 조건검색/철거 등은 취소 시 결과 영역을 숨기며 검색부의 미완료 안내가 남는다. 공동주택은 기존 잠정 결과 보존 정책을 따른다.

### 기본 표시 열과 표시 설정

순번과 `상세·위치` 동작 열은 아래 표의 데이터 열과 별도로 기본 표시한다.

| 화면 | 기본 데이터 열 | 숨길 수 없는 식별 열 |
| --- | --- | --- |
| 여러 주소 한 번에 | 입력주소, 건물명·동, 주용도, 연면적, 지상층, 지하층, 사용승인일, 조회 상태 | 입력주소, 건물명·동 |
| 건축물 조건검색 | 주소(도로명 우선), 건물명, 동, 주용도, 연면적, 지상층, 지하층, 사용승인일, 조회 상태 | 주소, 건물명, 동 |
| 공동주택 | 단지명, 주소(도로명 우선), 종류, 세대수, 사용승인일, 총 주차대수 | 단지명, 주소 |
| 철거·멸실 | 주소, 구분, 철거·멸실일, 용도, 연면적 | 주소 |
| 빈집 | 지번주소, 행정동, 등급, 건축년도, 기준일자 | 지번주소 |

- `표시 항목`에서 기존 추가 열을 선택하며 `기본 항목`/`전체 항목` 버튼으로 되돌린다. 조건검색의 새 `대장 수신`은 **해당 행의 수신 상태**이지 전체 조회 성공이나 위반 여부 판정이 아니다.
- 주소 기본 열은 도로명 주소가 비어 있으면 해당 레코드의 지번으로 표시한다. 기존 별도 지번 열은 추가 항목으로 유지한다. 다른 건물 주소로 대체하지 않는다.
- 설정은 **화면 메모리의 표시 설정만**이다. 로컬 저장소를 새로 사용하지 않으며 새로고침하면 기본 열로 돌아온다. URL·필터·History·엑셀·검색 범위에 넣지 않는다.
- CSS 표시만 바꾸므로 정렬·페이지·선택 상세·조회 데이터를 재생성하지 않는다. 모바일은 PC 열 선택과 독립적으로 기본 식별·핵심 열과 기존 카드 필수 정보를 유지하고, 기타 항목 펼치기도 보존한다.
- 숫자·긴 주소/이름은 원문 확인이 가능하다. 각 행에는 접힌 `원본 수치·자료 근거`를 추가했다. 표 헤더 `scope`/`headers`와 정렬 `aria-sort`도 연결한다.
- **엑셀은 전체 항목 저장**이다. 표시 열로 잘라내지 않는다. 기존 조회정보·UI 2단계 실제 결과 조건 시트도 유지한다. 공동주택 면적의 기존 엑셀 반올림은 제거하여 보관 값의 정밀도를 유지했다.
- 조건검색에서는 이미 수신한 표제부에서 필지 PNU와 안전한 원본 대장 ID만 결과 메타데이터로 넘긴다. 원본 행을 바꾸지 않으며 조건/정렬에 사용하지 않는다. 확인 가능한 식별자는 엑셀에도 추가하고, 안전하지 않은 숫자 ID를 반올림해 식별자로 만들지 않는다.

### 상세: 요약 → 세부정보 → 자료 근거

- 기존 개별 주소·폐쇄말소 카드 구조를 정리했다. 건물명/주소, 도로명·지번, 선택 동, 주·부속 구분, 주용도, 연면적, 층수, 승인일이 요약에 먼저 나온다. 구분이 없으면 임의로 주건축물이라고 정하지 않고 `주·부속 구분 미확인`으로 표시한다.
- 기존 규모·구조·주차 등은 `세부정보`, 원본 ID/필지/출처/수집일·연결 한계는 `자료 근거`로 분리했다. 공동주택 상세도 같은 계층을 사용한다.
- 층별·주차·오수·지역지구·이력·가설/공작물·대지권·기존 지도 탭은 제거하지 않았다. 기존 지연 로딩·캐시·gate와 보강 슬롯 갱신을 그대로 사용한다.
- GIS 높이/위반정보·대지권 보강 슬롯은 접힌 영역 밖에 남긴다. 필지 대표 범위·동별 연결 미확인·기준일·실패/재시도 안내를 숨기지 않는다. 빈집 지도 카드도 기준일·위치 범위를 본문에 두고 출처·수집일·식별자만 자료 근거에 모은다.
- 보강 도착 시 기존 슬롯만 갱신하므로 선택 동/탭/펼침을 재설정하지 않는다. 공동주택의 늦은 완료 스크롤도 제거했다.
- 인라인 상세에 키보드로 누를 수 있는 `상세 닫기 · 결과로`를 제공하고 닫으면 실행 요소로 포커스를 돌린다. 개별 주소에는 `검색으로 돌아가기`를 제공한다. 원래 단지명 링크/행 클릭도 유지하며 내부 버튼은 전파를 차단해 중복 실행하지 않는다.

### 목록·지도·상세 연결

**기존 목록을 유지하는 두 가지 동작**을 사용한다. 새 모바일 하단 패널이나 별도 패널 시스템은 만들지 않았다.

1. **지도에서 보기:** 해당 결과 바로 아래에서 기존 Leaflet과 VWorld 타일 프록시를 사용한다. 이미 연결된 도형을 우선 사용하고, 필요하면 기존 `apt_geo.json`을 한 번 읽어 **동일 PNU/단지 코드**의 참고 위치만 찾는다. 전체 API 재검색·일반지도 메뉴 초기화·다른 메뉴 취소는 하지 않는다. 닫으면 원래 버튼으로 포커스가 돌아온다. 모바일은 초기 드래그/핀치 조작을 끄고 명시적 켜기 버튼을 제공한다.
2. **건물 상세 보기 · 새 탭:** 기존 v1 주소 상세 URL을 사용한다. 원래 목록은 그대로 두고 해당 주소만 조회한다. 건축물 원본 대장 ID가 있으면 기존 `registry:...` 선택 식별자로 넘기고, 숫자 동명은 기존 입력 동 선택 방식도 사용한다. 안정적인 ID 없이 배열 인덱스로 영구 링크를 만들지 않는다.

- `Point`는 `좌표 위치 · 건물 윤곽이 아닙니다`, 도형은 `필지·참고 도형 · 선택 건물의 윤곽으로 확정하지 않습니다`라고 표시한다.
- 같은 필지의 현재 공동주택 정적 도형을 참고할 때는 개별 동 연결 미확인을 표시한다. 철거 기록의 경우 **철거 당시 도형이 아님**을 명시한다. 연결이 없으면 없다는 이유를 남기며 인근 다른 건물로 바꾸지 않는다.
- 다건 위치는 연결 기록을 선택할 수 있게 하고 도형을 함께 보여 주되 원본 수치·레코드는 합치지 않는다. 일반지도 다건 빈집 카드에는 **각 원본 ID별 `목록에서 보기`**가 있어 동일 지도 목록의 해당 행으로 포커스를 돌린다. 여러 단지가 같은 필지에 있으면 개별 상세 링크도 복수로 제공할 수 있게 했다.
- 일반지도에서 주소가 있는 공동주택/건축물은 주소 상세를 새 탭으로 연다. 빈집은 개별 건축물 식별이 검증되지 않아 건물 상세로 자동 확정하지 않는다.
- 새 탭을 닫거나 인라인 지도를 닫아도 원래 목록의 필터·정렬·페이지·선택·스크롤이 유지된다. 주소 상세 링크와 일반지도 선택은 기존 P3의 공유/뒤로/앞으로 복원 계약을 사용한다.

### 숫자·단위·날짜 규칙

`result-format.js`는 **표시 전용 순수 함수**이며 정렬/계산/필터/엑셀 값을 돌려쓰지 않는다.

| 항목 | 대표 표시 |
| --- | --- |
| 면적 | 최대 소수 2자리, 단위 `㎡`는 헤더/레이블/값에 명시 |
| 비율 | 최대 소수 1자리, `%` 명시 |
| 지수 | 최대 소수 2자리, 가격으로 환산하지 않음. 기존 지수 기준 미확인 유지 |
| 층수·세대수·대수 | 비음수 안전한 정수, 천 단위 쉼표. 음수/소수/비정상은 미확인 |
| 금액 | 확인된 원/천원 단위만 환산. 만원 이상은 만원 반올림하여 억/만원 대표 표기 하나, 작은 금액은 원 단위 표시 |
| 날짜 | 유효한 날짜만 `YYYY.MM.DD`. 월까지만 있으면 `YYYY.MM`, 연도만 있으면 `YYYY년` |
| 경과 | 정확한 날짜는 완료된 연수 `경과 N년`, 연/월만 있으면 `연도 차이 N년`으로 구분. 미래 값의 음수 경과는 표시하지 않음 |
| 없음 | 누락·공백·비유한 값은 미확인, 명시적 `해당 없음`은 그대로, 유효한 0은 0 |

REB 실제 예: `314507.575757576 천원` → **약 3억 1,451만원**. 도표·원본 단위와 요약 금액 표기를 구분하고, 접힌 근거에 원본 값·단위·`1천원=1,000원`·반올림 기준을 제공한다. 기존 접근 가능한 원본 시계열 표와 통계 출처/기준 불확실성 설명은 유지한다.

기존 수집/정규화가 이미 합산·보강한 값은 그 보관 값을 표시한다. 모든 보관 값을 원본 API의 개별 필드와 동일하다고 보증하지 않는다. 특히 기존 주차 합산의 미기재 폴백 같은 수집 의미를 이번 UI 작업에서 다시 정의하지 않았다.

### 남은 제한·미검증 범위

- **실제 로컬 Chromium**을 사용했지만 모바일은 터치/너비 에뮬레이션이다. 물리 휴대전화, iOS Safari, 실제 스크린리더는 미검증이다.
- API는 통제된 응답/지연/실패와 이전 실제 응답의 선택 필드 fixture를 사용하고, 행정동·빈집·단지·통계는 실제 저장 파일을 사용했다. 이번 단계에서 운영 외부 API 전수 조회·실제 배경 타일 품질·운영 속도를 검증하지 않았다.
- 인라인 지도는 연결 자료가 있는 항목의 **참고 위치**다. 도형/좌표가 없는 건물의 실제 위치를 새로 수집하지 않으며, 철거 당시 윤곽이나 빈집 개별 건물 일치를 확정하지 않는다.
- 인라인 지도 펼침과 표시 열은 공유 조건에 저장하지 않는다. 공유/이력은 기존 검색 조건·선택 식별자 계약을 유지한다. 새 탭 주소 상세는 v1 링크로 재현되지만 원본 ID가 없는 경우 동일한 개별 동/원본 기관 레코드를 확정하는 링크가 아니다. 해당 화면에서 후보/동을 확인해야 한다.
- `목록에서 보기`는 일반지도 내부의 **지도 결과 목록**으로 돌아간다. 별도 메뉴의 빈집 표를 강제로 재검색/초기화하는 연결은 만들지 않았다. 원래 표에서 연 인라인 지도와 새 탭 상세는 원래 표 자체를 그대로 유지한다.
- 기존 수집 단계의 합산/기본값/주소 보정과 최신성은 이번 표시 UI만으로 원본 미기재 여부까지 재판정하지 않았다. 결과표의 완료 상태는 자료 정확성이나 법적 상태를 보증하지 않는다.
- 검증 완료 후 사용자 요청에 따라 커밋·푸시·PR 머지를 진행한다. 화면 증거는 운영 배포 전 코드 기준이며 별도 배포 명령은 실행하지 않았다. Vercel 연동 시 푸시·머지로 자동 배포될 수 있다.
