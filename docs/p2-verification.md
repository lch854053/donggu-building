## 1. 증상 분석

목록은 `vacantlist_donggu.json` 648행, 지도는 `vacant_geo.json` 634행을 별도로 읽었다. 지도 생성 코드가 `baseDate`를 출력하지 않았고, ID를 만들지 않았으며, 도형을 얻지 못한 행은 출력에서 제외했다. 상세 기본 카드는 GIS와 대지권의 직렬 완료를 기다렸고, 공동주택 보충 조회는 선택 행정동에 관계없이 법정동 34개를 대상으로 했다.

360px 실제 브라우저 뷰포트에서는 문서 너비가 383px이었고 숫자 직접 입력은 없었다. 모바일 개선은 물리적 휴대전화가 아닌 Chromium 터치·모바일 에뮬레이션으로 검증했다.

## 4. 근본 원인과 빈집 데이터 처리 기준

### 현재 자료의 차이

검사 결과 전체는 [p2-vacant-audit.json](p2-vacant-audit.json)에 레코드 ID와 함께 남겼다.

| 항목 | 결과 |
| --- | --- |
| 기준 목록 원본 행 | **648레코드** (건물 수로 확정하지 않음) |
| 공백 정규화 지번주소 | 634종 |
| 같은 정규화 주소의 다건 그룹 | 13개, 합계 27레코드 (단일 주소 대비 추가 14행) |
| 보관 원본 필드가 완전히 같은 그룹 | 1개·2행. 두 행 모두 보존 |
| 기존 지도 행 | 634행. 목록에 대응하지 않는 주소/속성 행 2개 포함 |
| 보수적인 속성 대응 후 지도 표시 가능한 원본 레코드 | **638레코드** |
| 그 레코드들이 공유하는 서로 다른 도형 | **632개** |
| 같은 도형을 공유하는 그룹 | 5개·11레코드 (도형 대비 추가 6레코드) |
| 위치/레코드 대응 미확인 | **10레코드**, 삭제하지 않고 목록·지도 결과 목록·집계에 유지 |
| 원본 투영좌표 보유 | 648행 모두. 원본 좌표 보유가 실제 건물 위치 확인을 뜻하지 않음 |

638 = 632도형 + 공유 도형의 추가 6레코드이며, 648 = 638 + 미확인 10레코드다. 기존 지도에서 기준 목록에 대응하지 않는 항목은 `동명동19-2`, `계림동443` 2행이다. 이들을 임의로 목록의 다른 행에 연결하거나 새 건물로 추가하지 않았다. 미확인 10행 중 `동명동90-4`, `대인동161-2`는 주소 자체의 지도 대응이 없고, 나머지 8행은 같은 주소의 기존 지도 행과 연도 등 속성이 달라 레코드 대응을 확정하지 않았다.

동일 주소에서 연도·좌표가 다른 행이 있으며, 주소 보강 엑셀도 `법정동+면적+구조+등급`이 같은 여러 주소 중 첫 값을 선택했었다. 따라서 같은 주소/필지라는 이유만으로 동일 건물이라고 판정할 수 없다. 엑셀 키가 서로 다른 주소로 충돌하면 이제 첫 값을 고르지 않고 기존 주소 폴백으로 넘긴다. 법정동 이름만으로 얻은 폴백 주소는 기록하되, 이후 생성에서 그 주소를 개별 빈집의 확정 지도 위치로 만들지 않는다.

### ID와 범위

- 목록과 지도는 `loadVacantDataset()`의 동일한 기준 레코드 집합을 사용한다. 기존 파일은 보존하고 런타임에서 대응하며, 다음 수집부터도 같은 모델로 ID·기준일·출처·수집일을 생성한다.
- `recordId`: 원천 ID가 있으면 사용. 현재 보관 자료에는 없고, 운영 `/api/vacant?perPage=2` 실제 응답에도 ID 필드 없이 11개 원본 속성이 제공됐다(`totalCount=648`). 지금은 원본 `dong/kind/year/struct/tarea/grade/baseDate/x/y`의 결정적 64비트 지문과 같은 행의 출현 번호를 사용한다. 충돌은 오류로 감지하며 행을 합치지 않는다.
- 이 파생 ID는 **스냅샷 원본 레코드 ID**다. 원본 속성이 바뀌면 ID도 바뀔 수 있고, 완전히 동일한 사본끼리 어느 것이 어느 물리적 건물인지는 구분할 수 없다. 동일 입력의 행 순서가 바뀌어도 서로 다른 속성의 레코드 ID 및 ID 집합은 유지된다.
- `parcelId`: 필지 PNU로 별도 관리한다. `recordId`와 혼용하지 않는다. 주소는 검색·보강 후보 키일 뿐이다. 기존 도형 연결은 주소뿐 아니라 가용한 연도·구조·면적·등급·행정동·유형·도로명도 일치하고 도형 후보가 하나일 때만 허용한다. 건물 동일성을 확정하는 연결이 아니라 **필지/참고 도형 연결**로 표시한다.
- 지도 카드에서 같은 도형의 모든 레코드를 펼쳐 볼 수 있고 개별 ID·기준일·출처·주소 보강 기준을 확인할 수 있다. `계림동241-15`의 기준일 `2025-07-16`도 전달된다.
- 자료 기준일(`baseDate`), 실제 다음 수집 때 기록하는 `collectedAt`, 서비스 문서의 서버 `Last-Modified`를 구분했다. 기존 자료의 수집일 및 실제 배포일은 미확인으로 표시하며 추정하지 않았다.

### 대기·취소·완전성

- 상세의 기본 대장 카드부터 표시하고 GIS·대지권을 최대 2개 병렬 요청한다. 선택 탭·동을 다시 그리지 않고 보강 슬롯만 갱신한다. 보강 실패는 기본 카드를 막지 않으며 항목별 재시도 가능하다.
- 공동주택 기본 목록은 먼저 잠정 표시한다. 후속 보강 뒤 원래 캡처한 연도/면적·미확인 조건을 최종 적용하고 정렬·페이지·선택 상세를 보존한다. 초기 잠정 집계가 최종 집계와 다를 수 있음을 명시한다.
- 계림2동의 보충 조회는 선언된 법정동 관계와 번지→행정동 매핑의 **합집합**인 `10900/11000` 모두를 조회한다. 알려진 단지에 해당하는 필지만 골라 전체 범위를 생략하지 않는다. 합성 누락 관계 테스트도 포함한다.
- 건축물 조건검색과 지도는 수신 결과를 잠정 표시한다. 지도에서는 새 조회 즉시 이전 목록/레이어를 지운다. 지도 도형 실패와 검색 데이터 실패의 P1 안내는 분리된 채 유지한다.
- 공동주택 동시성은 5→2, 나머지 페이지 수집은 2 유지. 일시 오류만 기존 백오프(최대 3회)를 사용한다. 실패 보충 페이지 및 실패 표제부만 재시도하며 성공 데이터는 보존한다. 보강 목록 파일 실패도 정상 0건/전체 완료로 숨기지 않는다.
- 새 검색/초기화/취소는 세대를 변경하고 대기 큐의 다음 요청을 막는다. 이미 전송된 공유 요청은 다른 호출자가 있을 수 있어 모두 강제 중단하지 않지만, 늦은 응답·진행 타이머가 현재 UI를 바꾸지 못한다. 비동기 재시도 보강 도중 조건이 바뀌면 행과 조회정보도 함께 커밋하지 않는다.

### 캐시 정책

- 라이브 성공 응답: 대상 엔드포인트 + 정렬된 전체 파라미터 키, 기본 2분. 정상 빈 응답은 최대 30초. 단지 기본 목록·네트워크 K-apt 기본/상세는 5분.
- 건축물 동·페이지 원본 캐시는 2분, 최대 250개. 필지/보충 요청 캐시도 최대 250개. 진행 중 동일 키는 하나의 Promise로 합치고 반환 데이터는 복제한다. 오류 응답은 저장하지 않는다.
- 공통 빈집 파일 스냅샷은 10분. 원본 실패는 오류, 지도 파일만 실패하면 원본은 보존하고 그 스냅샷을 장기 캐시하지 않는다. 다음 조회로 위치 파일을 재시도한다.
- 정적 K-apt 파일에 이미 병합된 기본/상세는 재사용하고 검색 때 다시 파일을 읽는다. 정상 캐시 재사용·P1 필지별 상세 캐시는 유지한다.

## 6. 검증 결과

### 성능: 같은 통제 조건의 개선 전/후

운영 외부 API를 반복 스캔하지 않기 위해 로컬 실제 Chromium 브라우저에서 동일한 응답·요청당 80ms 지연을 주입했다. 수정 전 `f3b03fb`와 수정 후를 각각 독립 컨텍스트 3회(첫 조회), 각 컨텍스트에서 1회씩 반복 조회(3회) 측정했다. 아래는 **중앙값**, ms 단위다. 최초는 결과 영역의 visible DOM 갱신 시점이며, 렌더 페인트 성능 점수는 아니다. 기본 행정동·정적 화면 초기화는 측정 전에 완료했다.

### 남은 제한

- 물리적 휴대전화·iOS Safari·Android Chrome 실기기 및 실제 보조기술(스크린리더)은 검증하지 않았다. 모바일 에뮬레이션 결과나 ARIA/포커스 검사를 실기기·스크린리더 검증이라고 부르지 않는다.
- 원천 건물 식별자가 없어 동일 주소 다건 및 완전 동일 행의 물리적 건물 수, 원본 투영좌표의 개별 건물 정확성은 확정할 수 없다. 파생 ID는 영구적인 건물 ID가 아니다.
- 기존 지도와 대응하지 않는 10레코드 및 지도 단독 2행은 원본 조사표/공급자 확인이 필요하다. 주소만으로 임의 보정하지 않았으며 감사 JSON에 별도 남겼다.
- 운영 키를 사용한 수집기 전체 실행·대량 VWorld 재수집·실제 월간 갱신은 수행하지 않았다. 생성 로직은 모의 입력·응답으로 검증했고, 기존 정적 파일은 그대로다. 도형 급감 시 게시 중단 가드는 유지된다.
- 성공한 API 페이지들이 같은 시점의 원본 스냅샷이라는 보장까지 제공하지는 않는다. 기간 내 성공 캐시의 갱신 지연은 위 TTL 정책을 따른다.
- 일부 요청은 이미 전송된 뒤에는 완료될 수 있다. 화면 보호는 취소 신호 하나에 의존하지 않고 세대·조건·소유권 검사로 보장한다.
- 이 문서의 측정·화면 증거는 운영 배포 전 코드 기준이다. 이후 사용자 요청에 따른 Git 통합과 Vercel 자동 배포 여부는 저장소 PR·배포 기록을 참조한다. 별도 배포 명령은 실행하지 않았다.
